# 08 · 测试与验证

项目做过两轮针对真实数据与核心流程的 QA 回归，并保留了完整的测试报告（`deliverables/software-company/gaokao-realdata-qa-report.md`）与自动化测试代码。

## 1. 自动化测试

### 后端单测（Vitest + Supertest）

`gaokao-backend/src/__tests__/auth.test.ts`（约 25KB）覆盖认证链路：

- 注册成功 / 邮箱重复
- 验证码发送、校验、过期、重复使用
- 登录成功 / 密码错误
- 连续失败 5 次锁定 15 分钟
- JWT 签发与受保护路由访问
- 登出

运行方式：

```bash
cd gaokao-backend
npm test           # vitest run
npm run test:watch # 监听模式
```

配置见 `vitest.config.ts`。

### 数据核对脚本

`scripts/` 下的 `checkCounts.ts`、`debugData.ts`、`testParser.ts`、`testRecommend.ts`、`quickTest.ts` 用于：

- 核对各表入库记录数
- 验证 Markdown 源数据解析器
- 端到端跑一次推荐流程并检查结果

## 2. 两轮 QA 回归

### 第一轮：FAIL

测试工程师从真实数据链路切入，发现两个真实 Bug 和一个数据问题：

| 编号 | 问题 | 根因 |
|---|---|---|
| Bug 1 | Step 1 选科覆盖率、Step 3 批次线页面 loading 永远为 true | `useEffect` 竞态 + 把缓存对象放进依赖数组，导致重复触发 |
| Bug 2 | Step 2 显示「超过一本线」时硬编码为 530 分 | 分数阈值写死，未按省份/年份从数据读取 |
| 问题 3 | `subject_coverages.province_code` 全为 NULL，无省份差异 | 导入脚本未正确写入省份字段 |

### 第二轮：PASS

修复后重新验证，结论 `IS_PASS = YES`：

| 检查项 | 结果 |
|---|---|
| Step 1 选科覆盖率 | 约 90%，正常渲染 ✅ |
| Step 2 位次与批次线 | 585 分 → 位次 46934、超特殊类型控制线 46 分 ✅ |
| Step 3 批次线 | 本科 425 分、特控 539 分，与源数据一致 ✅ |

## 5. 尚未覆盖的测试

如实说明，以下方面**没有**自动化测试或压测数据：

- 端到端 UI 自动化测试（UI 验证以手动 + 截图记录为主）
- 高并发压测（架构文档设定了 P95<500ms、峰值 QPS≥10000 等目标，但**未实际压测**，见 [10 · 实现边界与后续规划](10-实现边界与后续规划.md)）
- 多省份全量数据的完整性校验（当前仅验证样本省份）
- LLM 输出质量的量化评估（理由准确性、purity 合理性为人工抽查）
