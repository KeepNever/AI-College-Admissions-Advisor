# 05 · 数据库设计

## 1. 多 Schema 划分

数据库使用 PostgreSQL 16，通过 Prisma 的 `multiSchema` 特性把 14 个模型划分到三个业务 Schema，实现逻辑隔离：

```
prisma/schema.prisma
├── data schema  ——  基础数据（省份、院校、专业、录取分数、招生计划、批次线……）
├── app  schema  ——  应用数据（推荐结果、风险诊断、用户、验证码）
└── rec  schema  ——  推荐数据（位次映射表）
```

划分依据：基础数据变动频率低、体量大；应用数据随用户请求增长；推荐映射表可按考季独立刷新。分 Schema 后便于分别做权限控制、备份与清理。

## 2. 模型清单

### data Schema（10 个）

| 模型 | 表名 | 关键字段 | 唯一约束 / 索引 |
|---|---|---|---|
| `Province` | provinces | code(PK)、examMode、totalScore | code 主键 |
| `University` | universities | code、name、tags[]、is211/985/doubleFirst | code 唯一 |
| `Major` | majors | code、name、category、subjectRequirements[] | code 唯一 |
| `AdmissionScore` | admission_scores | 院校/专业/省份/年份/批次、min/avg/maxScore、min/avg/maxRank、planCount | `[provinceCode, year, universityId, majorId, batch]` 联合唯一 |
| `UniversityPlan` | university_plans | 同上维度 + tuition、subjectRequirements[] | 同维度联合唯一 |
| `ProvinceBatchLine` | province_batch_lines | 省份/年份/科类/批次、score、source | 四维联合唯一 |
| `ProvinceRankSegment` | province_rank_segments | 省份/年份/科类、score、rank、totalCount、source | — |
| `SubjectCoverage` | subject_coverages | 省份/年份/科目组合、coveragePct、totalMajors、source | `[provinceCode, year, subjects]` 唯一 |
| `CityUniversityMap` | city_university_map | 城市名、院校、省份 | `[cityName, universityId]` 唯一 |

> `AdmissionScore` 与 `UniversityPlan` 的联合唯一约束是防止数据重复导入的关键：同一省份 + 年份 + 院校 + 专业 + 批次只允许一条记录。

### app Schema（4 个）

| 模型 | 表名 | 关键字段 | 说明 |
|---|---|---|---|
| `Recommendation` | recommendations | result(Json)、resultHash、generatedAt、expiresAt | 推荐结果缓存，带过期时间 |
| `RiskCheck` | risk_checks | name、status、detail、sortOrder | 风险诊断项 |
| `User` | User | email(唯一)、passwordHash、isVerified、wechatOpenId、failedAttempts、lockedUntil | 用户与登录安全状态 |
| `VerificationCode` | VerificationCode | email、codeHash、type、expiresAt、used、userId | `@@index([email, type])` 加速验证码查找 |

### rec Schema（1 个）

| 模型 | 表名 | 关键字段 | 说明 |
|---|---|---|---|
| `RankLookup` | rank_lookups | score、provinceCode、rank、sameScore、rangeMin、rangeMax | `[score, provinceCode]` 唯一；分数→位次的核心映射 |

## 3. 字段设计要点

- **数组类型**：`University.tags`、`Major.subjectRequirements`、`SubjectCoverage.subjects` 使用 PostgreSQL 原生 `String[]`，省去中间关联表。
- **数据溯源**：批次线、位次段、选科覆盖三张表都有 `source` 字段，记录数据来源（可追溯到具体 md 源文件），便于核对与更新。
- **时间戳**：核心表均有 `createdAt` / `updatedAt`，部分使用 `Timestamptz(6)` 保留时区。
- **UUID 主键**：业务实体用 `gen_random_uuid()`，避免自增 ID 在分布式场景下的冲突。

## 5. 数据导入

`gaokao-backend/scripts/` 下有一组导入脚本，把解析后的真实数据写入数据库：

| 脚本 | 用途 |
|---|---|
| `importBatchLines.ts` | 导入批次线 |
| `importRankSegments.ts` | 导入一分一段位次 |
| `importSubjectCoverage.ts` | 导入选科覆盖率 |
| `importAdmissionScores.ts` | 导入录取分数 |
| `importUniversityPlans.ts` | 导入招生计划 |
| `importMajors.ts` | 导入专业 |
| `importCityUniversityMap.ts` | 导入城市-院校映射 |
| `importAll.ts` | 一键全量导入 |

配套的 `markdownParsers.ts`（约 32KB）负责把源数据文件解析为结构化记录——这是数据工程中工作量最大的部分之一。

## 6. 实际入库规模（已验证）

| 数据表 | 记录数 | 验证方式 |
|---|---|---|
| province_batch_lines | 114 条 | `checkCounts.ts` 脚本 + QA 报告 |
| province_rank_segments | 172 条 | 同上 |
| subject_coverages | 11 条 | 同上 |

QA 抽样核对：广东物理类本科批 425 分、特殊类型控制线 539 分；585 分对应位次 46934、同分人数 1262，与源数据一致。

> 完整数据覆盖（如全 31 省、全部院校招生计划）属于后续数据工程工作，当前为可验证的样本规模。详见 [10 · 实现边界与后续规划](10-实现边界与后续规划.md)。
